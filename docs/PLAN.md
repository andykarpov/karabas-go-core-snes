# План порта SNES на Karabas Go / Mini / Mini G

Цель: ядро SNES для трёх плат (Xilinx Spartan-6 XC6SLX25-2, ISE 14.7, XST): одно ядро, три верха, как у `karabas-go-core-nes` и `karabas-go-core-tsconf`. Первая плата — Mini G (HDMI, PCM5102), затем Mini (HDMI, sigma-delta), затем Go (VGA, PCM5102).

Затрагиваемые репозитории:

| Репозиторий | Что меняется |
|---|---|
| `karabas-go-core-snes` | ядро: upstream RTL, верхи плат, контроллеры памяти, видео, загрузчик, сохранения |
| `karabas-go-modules` | ничего нового на старте (`kg_mcu`, `kg_pll`, `kg_dcm`, `kg_*` память, `zhdmi`, `kg_osd_overlay`, ЦАП); позже `kg_bk_ram` (общий с NES, Ф2 его плана) |
| `karabas-go-firmware` | на старте ничего (тип `fileloader`); для `.srm` — `CMD_BK_MOUNT` / `CMD_IMG_FLUSH` из плана NES |
| `karabas-go-tools` | `core.json` нового ядра; поле `saves` — вместе с NES |

## 0. Исходные данные

### Платы

Все три платы одинаковы в том, что важно для SNES:

- FPGA XC6SLX25-2: 15 032 LUT6, 3 758 слайсов, 52 RAMB16 (117 КБ), 38 DSP48A1.
- SRAM 2M x 16 (4 МБ, две микросхемы 2M x 8 с общим адресом `MA[20:0]`, `MWR_N[1:0]` / `MRD_N[1:0]`), асинхронная, 10 нс.
- SDRAM MT48LC16M16A2 (32 МБ, 16 бит), на всех трёх платах.
- MCU-линк `kg_mcu`: загрузчик файлов, OSD, HID (клавиатура, мышь, `joy_l` / `joy_r` по 13 бит), RTC, file mounter (`ENABLE_IMG`).
- Видео: Go — VGA (`VGA_R/G/B` 8 бит), Mini / Mini G — HDMI (`zhdmi_top`, умеет 32 кГц аудио — родная частота DSP SNES).
- Звук: Go и Mini G — PCM5102 (`kg_pcm5102`), Mini — `kg_sigma_delta_dac`.

### Что нужно SNES

| Память | Объём | Кто обращается | Темп |
|---|---|---|---|
| ROM картриджа | до 4 МБ (ExHiROM до 6–8 МБ) | CPU, DMA | ≤ 1 доступ на цикл CPU (6/8/12 mclk) |
| WRAM | 128 КБ | CPU, DMA | как ROM (доступы CPU взаимоисключающие) |
| BSRAM (сейвы) | 2–256 КБ (обычно 2–32 КБ) | CPU, сохранение | как ROM |
| VRAM | 64 КБ (2 x 32K x 8, в mode 7 разные адреса у двух половин) | PPU, CPU через порты | 1 чтение (2 байта) на точку = 4 mclk |
| ARAM | 64 КБ | SPC700, DSP | ~1 доступ на точку |
| CGRAM, OAM, буферы PPU/DSP | ~2 КБ | внутри | BRAM |

Mclk = 21,477 МГц (NTSC), 21,281 МГц (PAL). Ресурсов на «всё в BRAM», как у MiSTer, нет: VRAM + ARAM + WRAM = 256 КБ при 117 КБ BRAM.

Почему не snestang целиком: его SV-части XST тоже не понимает (как и MiSTer), код расходится с upstream, а исправления совместимости идут в SNES_MiSTer / SNES_FPGA. ## Архитектура (предварительно, проверяется в Ф0)

### Клоки

Один PLL от 50 МГц: VCO 687,5 МГц (M = 55, D = 4):

- `clk_sys` = mclk 21,484 МГц (/32, +0,03 % к NTSC) — вся SNES, `kg_mcu`, OSD, видео;
- `clk_mem` = 85,94 МГц (/8) = 4 x mclk, фаза 0 — контроллеры SDRAM / SRAM (связанные клоки, как в snestang и tsconf);
- HDMI: `kg_dcm` 5 x `clk_sys` (107,4 МГц) для сериализатора.

PAL на той же частоте (−0,9 % у 50 Гц) — на первом этапе, отдельный PLL потом при необходимости.

### Память

Вариант A (основной) — по раскладке MiSTer, без многоканального SDRAM:

| Где | Что | Почему |
|---|---|---|
| SDRAM | ROM (до 8 МБ), WRAM 128 КБ | Один канал (CPU / DMA / загрузчик), это `sdram.sv` MiSTer / `USE_SIMPLE_SDRAM` MiST на ~85 МГц — проверенный тайминг. Рефреш в паузах CPU. |
| SRAM | ARAM 64 КБ, BSRAM до 256 КБ, (резерв: VRAM — вариант B) | Асинхронная 10 нс, без рефреша и банков: два слота на mclk (SMP/DSP и CPU/сохранение), детерминированная задержка. |
| BRAM | VRAM 64 КБ (32 RAMB16), CGRAM, OAM, буферы PPU / DSP, микрокод, строковый буфер, OSD | Как `BRAM_LEVEL_1` MiST. |

Вариант B (если BRAM не хватит): VRAM в SRAM. На точку (4 mclk = 16 клоков `clk_mem`) нужно VRAM1 + VRAM2 (разные адреса в mode 7) + ARAM + CPU — 4 доступа по 3 клока, помещается. Вариант C (запасной): 3-канальный SDRAM snestang (`sdram_cl2_3ch.v`, CPU / ARAM / VRAM).

### Видео

Без кадрового буфера (256 x 224 x 15 бит = 860 Кбит — нет места): **удвоитель строк** на mclk. Строка SNES = 1364 mclk, удвоенная = 682 → 31,5 кГц, 524 строки, 60,1 Гц; пиксельный клок = `clk_sys`, точка SNES = 2 пикселя (hires 512 — 1 пиксель), отдельного видеоклока нет. Буфер — 2 строки x 512 x 15 бит (1–2 RAMB16). HDMI: `zhdmi_top` с DE-окном (как nanomig: 908 x 625 Amber шло прямо в zhdmi), VGA Go — те же сигналы на ЦАП. Риск: нестандартный 682 x 524 при 21,48 МГц — проверить на нескольких мониторах / ТВ; запасной путь — кадровый буфер в SDRAM (её почти не нагружает вариант A) и честные 480p.

### Загрузчик и тип картриджа

- `kg_mcu` file loader → SDRAM (ядро в reset). Расширения `.sfc`, `.smc`, `.bin`; заголовок копировщика (512 Б) — по `IOCTL_SIZE` (размер mod 1024 = 512), если ядро грузится через `FILE_CMDS = 0`, иначе по оценке заголовка с обоими смещениями.
- Определение LoROM / HiROM / ExHiROM **в ядре**: прошивка Karabas (в отличие от ARM MiST, `ioctl_index[7:6]`, и RISC-V snestang) заголовок не разбирает. При загрузке захватываются 32-байтные кандидаты заголовка (`0x7FC0`, `0xFFC0`, `0x40FFC0`, плюс `+512`), после загрузки — оценка по правилам `parse_snes_header()` snestang / bsnes (тип карты, размер ROM, контрольная сумма и её дополнение, вектор reset). Дальше — логика `rom_type` / `rom_mask` / `ram_mask` из `SNES.sv` MiST (DSPn, OBC1, GSU и т.д.). OSD-переключатель «ROM type: Auto / LoROM / HiROM / ExHiROM» на случай ошибки.

### Ввод

`joy_l` / `joy_r` (13 бит) → регистры сдвига SNES-джойпада (`JOY1_DI` / `JOY2_DI` / `JOY_STRB` / `JOY*_CLK` у `main`); `ioport.sv` MiSTer (SV) — переписать на Verilog. Раскладка: B Y Select Start ↑ ↓ ← → A X L R; клавиатура — через `hid_parser` по образцу NES. Мышь SNES (`MS_*`) и мультитап — позже.

## Ф0. Подготовка и проверка «влезет ли» (решающая)

1. Репозиторий как у NES: `modules/` сабмодулем, `src/Makefile` (три платы, шаги xst / impl / core / report), `karabas_<board>_top.prj/.xst/.ut/.ucf` из `karabas-go-core-nes`, `make_core.py` симлинком, `CLAUDE.md`, `docs/UPSTREAM.md` (коммиты, таблица файлов, языки, что заменено).

3. **Пробный синтез XST одного `main`** (память — порты наружу, `-iobuf NO`), на `clk_sys` 21,48 МГц: LUT, регистры, RAMB16, DSP48, оценка тайминга. Варианты:
   - `main` без доп. чипов;
   - `+ DSPn` (DSP-1: Super Mario Kart, Pilotwings);

5. Решение по таблице результатов записать сюда: какой RTL (VHDL SNES_FPGA / Verilog snestang / смесь по модулям), вариант памяти A/B/C, есть ли место для DSPn.

Если `main` один не влезает в ~12k LUT — искать в `.syr` память, развёрнутую в LUT (как с floppy у nanomig: асинхронное чтение, несколько портов) и переписывать её на `kg_*`; микрокод 65C816 / SPC700 — в BRAM-ПЗУ.

### Результаты Ф0 (2026-10-25)

Импорт: `src/rtl/snes/` — `rtl/` SNES_FPGA `b7c50e5` без доп. чипов (кроме `DSP_LHRomMap`, `DSPn`, `OBC1`, `SRTC`), `bram_kg.vhd` вместо `bram.vhd` (altsyncram → выводимая XST память). Правки upstream помечены `karabas:`:

- `SNES.vhd`: без Game Genie (`cheatcodes.sv` — SV); выражения в `port map` — сигналы (XST их, впрочем, принимает; это для ghdl).
- `CPU.vhd`: `case` с `others` (ошибка XST HDLCompiler:299).
- `main.v`: объявления `SS_*` до первого использования (XST: «already implicitly declared»).
- `DSP_LHRomMap.vhd`: generic `USE_DSPn` integer (XST не передаёт параметр Verilog в generic std_logic).
- `65C816/MCode.vhd`, `SPC700/MCode.vhd`: таблица микрокода читается регистром без сброса → BRAM; значение сброса / STATE 0 — флагом. Проверено `src/sim/eq/run_eq.sh` (ghdl, против upstream, случайные входы; тест ловит обе мутации).
- `DSPn.vhd`: ПЗУ из `.txt` (`src/tools/mif2bin.py` из `.mif` upstream; файлы прошивок DSP в git не кладутся, см. вопросы).

XST сам принял VHDL upstream, кроме пунктов выше. Пробный синтез — `src/fit/run_fit.sh [top] [area]` (XST, `-iobuf NO`, память наружу, оценка XST до map / par):

Выводы на сейчас:

- **RTL — VHDL SNES_FPGA.** Verilog snestang через XST не меньше (17,0k против 16,3k по модулям) и отстаёт от upstream.
- Без доп. работ не влезает: 12,3k SNES + ~3k обвязки (`kg_mcu`, zhdmi, OSD, контроллеры SDRAM / SRAM, удвоитель, загрузчик) ≈ 15k LUT = 100 %. Нужно ещё ~2,5–3k LUT.
- **BRAM:** 18 занято самой SNES (микрокод 14). С VRAM в BRAM (32) — 50 из 52, без места на строковый буфер и OSD. → **вариант B: VRAM в SRAM**, BRAM остаётся на микрокод, буферы и DSPn.
- **Тайминг:** критический путь — микрокод 65C816 → АЛУ → регистр A (46,7 нс при бюджете 46,5). Регистры 65C816 обновляются только по разрешению такта CPU (раз в 6–12 mclk), поэтому — мультицикловое ограничение на внутренние пути P65C816 (как `TS_CPU_MC` у nanomig), после проверки, что все его регистры под `CE`.
- Кандидаты на экономию LUT (по `Macro Statistics` .syr):
  1. SCPU без процессора — ~3,3k: регистры DMA (8 каналов x 11 байт, массивы `DMAP`, `A1T`, `DAS`, `A2A`, `NTLR`...) читаются и инкрементируются по индексам `DMA_CH` / `DMA_CH_IND` / `DMA_CH_LATCH` — 489 мультиплексоров по 16 бит. Переписать на регистровый файл в распределённой RAM (одна запись за такт, чтение по индексу) — с тестом эквивалентности против upstream.
  2. DSP — 4,8k: 9 сумматоров 34 бит, 10 умножителей (уже DSP48). Разобрать подробнее.
  3. PPU — 4,0k.

### Решения после Ф0 (2026-10-25)

- Память — **вариант B**: VRAM в SRAM вместе с ARAM и BSRAM (`rtl/mem/snes_sram.v`), ROM и WRAM в SDRAM (`rtl/mem/snes_sdram.v`), BRAM — микрокод, DSPn, буферы. DSPn включён (прошивки DSP в git с разрешения автора).
- Тест на реальном железе важнее HDMI-аудио: первая сборка выводит **DVI** (`dvi.vhd` + `tmds_serializer` modules, ~230 LUT); `hdmi_tx` zhdmi — 2 240 LUT, HDMI NES — 1 094 LUT, не помещаются вместе с SNES. Звук — PCM5102. HDMI-аудио вернуть после экономии LUT.
- Регистры DMA SCPU в однопортовую RAM не переводятся: в одном такте бывают две записи в одно поле с разными индексами (`NTLR(DMA_CH)` в HDS_INIT и `NTLR(DMA_CH_LATCH)` после FETCH_SCANLINE_COUNTER, так же `DAS`). Переписывать только вместе с тестами DMA / HDMA на ROM.

Битая графика или звук — SRAM (VRAM, ARAM).

## Ф2. Память и загрузчик

*Сделано (симуляция)*: `snes_sdram.v` (CL2, 6 тактов на доступ, рефреш между запросами, окно захвата чтения при круговой задержке платы 3,2–11,5 нс), `snes_sram.v` (3 такта на доступ, /WE в среднем такте), `snes_phase.v`; запросы-переключатели как у MiST, ответы на фазе 0 (`TS_MEM_ANSWER`). Загрузчик через `kg_fifo`, `snes_hdr.v` — заголовок после загрузки чтением из SDRAM (оценка кандидатов, заголовок копировщика). Тесты: `sim/mem/run_mem_sim.sh`, `sim/sys/run_sys_sim.sh`. Не сделано: очистка WRAM / ARAM при старте (значения MiSTer), загрузка `.spc`.

- Контроллер SDRAM: ROM + WRAM, один канал на `clk_mem`, CL2; основа — `sdram.sv` MiSTer (перевод на Verilog) или `sdram_nano.v` / `sdram_cl2_3ch.v` snestang (уже Verilog), рефреш, порт загрузчика. Тесты: модель SDRAM с проверкой таймингов (как `run_fastram_sim.sh` nanomig).
- Контроллер SRAM: слоты по фазе mclk (ARAM — SMP/DSP, CPU — BSRAM, третий — сохранение / загрузчик), задержка данных под ожидания `main` (`READ_PULSE`, `SYSCLKR_CE`, как у MiST). Бюджет SRAM в ucf.
- VRAM в `kg_sdpram` / `kg_tdpram` (2 x 32K x 8).
- Загрузчик ROM, захват и оценка заголовка, `rom_type` / маски, очистка WRAM / ARAM при старте (значения из OSD MiSTer: `9966`, `00FF`, `55`, `FF` — для игр, зависящих от мусора в RAM).
- Тесты (iverilog / ISim): загрузчик по MCU-линку → SDRAM-модель → чтения CPU; определение типа на наборе заголовков реальных ROM (LoROM, HiROM, ExHiROM, с копировщиком и без).

## Ф3. Первый запуск SNES

- `main` в верхе Mini G, удвоитель → HDMI, звук 32 кГц → zhdmi (родной `SAMPLERATE = 32000`) и PCM5102, пики `audio_peaks.v` для прошивки.
- Джойпады, Reset (OSD / F12), пауза SNES во время работы MCU.
- Симуляция: verilator-обвязка snestang (`verilator/`, SDL) как образец — прогон ROM, кадры в файл; тестовые ROM: PeterLemon (CPU / PPU / SPC700), blargg `spc_*`, `krom`; затем игры: Super Mario World (LoROM, BSRAM), Zelda ALttP (BSRAM), Super Metroid, DKC (HiROM 4 МБ), Chrono Trigger (HiROM 4 МБ), Tales of Phantasia (ExHiROM).
- Тайминг: «All constraints were met», LUT / слайсы — в `CLAUDE.md` после каждой сборки.

*Проверено на железе (Mini G, сборка 26102503, 2026-10-25)*: картинка 640 x 480 на мониторе автора (скейлер под матрицу iPad 3, требовательный к таймингу), OSD (был на знакоместо правее — `H_OFFSET` 104 → 96 в 26102504), игры грузятся и идут. Звук по HDMI нет (выход DVI), на PCM5102 — тот же `kg_pcm5102` и пины, что у NES. Клавиатура (как `hid_parser` NES) — `rtl/snes_kbd.v` с 26102504. Джойстики ещё не проверены.

Не сделано: HDMI-аудио — нужен лёгкий передатчик (zhdmi 2240 LUT, свободно ~2,3k LUT при слайсах 99 %).

## Ф4. Mini и Go

*Сделано (сборка 26102502, не проверено на железе)*: `karabas_mini_top.v` (DVI, сигма-дельта на AUDIO_L/R), `karabas_go_top.v` (VGA через ЦАП платы, `V_CLK` = clk_pix, PCM5102); общая часть — `rtl/snes_core.v`. Все три платы: ~12,6k LUT (83–84 %), слайсы 98–99 %, все ограничения выполнены. Видео всех плат — VESA 640 x 480 на clk_pix 25,10 МГц (второй PLL), см. `snes_video.v`.

*Сборка 26102503 (видео)*: 26102501 и 26102502 на мониторе автора — «no signal». Причина: выходная развёртка шла от строк SNES, а в сбросе (до `CMD_INIT_DONE` MCU, во время загрузки ROM) PPU стоит и HSYNC нет — на выходе ни синхроимпульсов, ни OSD; кроме того, каждая вторая строка была 797–798 тактов, кадр 524 строки. Теперь развёртка свободная, ровно 800 x 525 (PAL 625) на clk_pix = clk_sys x 40 / 34 = 25,21 МГц (второй PLL; x5 для сериализаторов — DCM от clk_pix, как в NES: x 47 / 40 с x5 на одном PLL требует VCO 1007 МГц, а предел 1000), кольцо из 4 строк SNES (+2 RAMB16), кадр подстраивается к кадру SNES длиной 256 строк после события захвата (801–802 такта, остальные строки 800; захват за один кадр); без SNES — чёрный экран с OSD. `sim/sys/tb_video.v`: тайминг в работе, при остановленном SNES и в PAL, фаза кадра к SNES (ловит отключённую подстройку), сторожевой таймер (ловит старую версию).

*Сборка 26102505 (interlace)*: в 26102504 у автора в R-Type экран гас, а звук шёл. Вероятная причина (не подтверждено на железе): PPU в interlace (`BGINTERLACE`) даёт поля по 263 и 262 строки (PAL 313 / 312), а подстройка добавляла к выходному кадру длину *прошлого* кадра SNES — через кадр промах на строку SNES (~1605 тактов), вне окна захвата, и выход прыгал на строку 49: кадры 525 / 528 строк с рваной строкой в 457 тактов. Теперь выходной кадр после события повторяет кадр SNES двумя раньше (той же чётности поля; P — от события до события в clk_pix) плюс отклонение события: c = d + P − 420000 (PAL 500000), разложено на 512 строк от 51-й (до 37-й следующего кадра; строки 800–805, строки 38..50 ровно 800), окно захвата ±3 строки; захват за 2–3 кадра. `tb_video` — ещё фазы NTSC interlace, PAL interlace (лишняя точка в последней строке), overscan (239 строк: видно 464 из 478 выходных — нижние обрезаются, как и было). Старая версия на новом тесте — 52 ошибки.

*Сборка 26102600 (PAL 576p)*: R-Type в 26102505 всё так же уходит в «no signal». Образ европейский: Region = Auto по заголовку включает PAL, а выход PAL был 800 x 625 строк при 50 Гц (DE 480 строк) — такого режима нет ни в VESA, ни в CEA, и монитор автора его не показывает. Interlace как причина не подтвердился (исправление 26102505 остаётся: оно нужно и само по себе). Переключить Region на NTSC для проверки нельзя: OSD типа `fileloader` пункты core.json не показывает. Теперь PAL — настоящий CEA 576p: 864 x 625 (HS 64, DE 720 с такта 132, VS 5 строк, DE 576 строк с 44-й), клок 600 / 22 = 27,27 МГц — третий выход главного PLL; BUFGMUX выбирает его по `pal` системы (регион картриджа), ×5 DCM сбрасывается на 256 тактов clk_sys после смены. Картинка 512 x 448 по центру (x 104, строка 64 окна), overscan 478 строк влезает целиком; событие захвата на строке 106, коррекция на строках 108..619 (864–871 такт). OSD в PAL получает сдвинутые синхроимпульсы (+28 тактов, +58 строк) — те же `H_OFFSET` / `V_OFFSET`. Найдено тестом: c в PAL interlace доходит до ~5000 (d до 3 строк + 3400), 13 бит не хватало и захват падал на c = d — теперь 14 бит. Смена режима начинает новый кадр сразу (иначе кадр PAL шёл на клоке NTSC, 41 мс без VS). `tb_video`: клок теста переключается с режимом, проверки 576p, фаза PAL overscan, место синхроимпульсов OSD; копия без `pal` — 67 835 ошибок.

*Проверено на железе (Mini G, 26102600, 2026-10-26)*: R-Type (Europe) в 576p50 — на мониторе автора всё так же «no signal». Монитор держит, судя по всему, только 60 Гц (NES работает: её кадровый буфер всегда 60 Гц). Сборки Mini / Go 26102600 остановлены автором: в git Mini и Go — 26102505 (PAL ещё 800 x 625), Mini G — 26102600.

*Сборка 26103001 (вариант 1, Mini G)*: Region Auto теперь всегда NTSC, регион из заголовка не используется (`pal_r` = 1 только при явном PAL в OSD). Выход всегда 640 x 480 при 60 Гц; PAL-игра идёт на ~20 % быстрее, звук тоже. Код 576p остался. Риск: игры с проверкой региона через `$213F` могут показать экран-предупреждение. LUT 12 997 → 12 862 (−135: сравнение региона из заголовка ушло), слайсы 99 %, все ограничения выполнены. Проверено на железе: Alien 3 и R-Type (E) работают, R-Type показывает предупреждение о регионе.

*Сборка 26103002 (Mini G)*: (1) PAL_ID: бит PAL в `$213F` берётся из региона заголовка при Auto (тайминг остаётся NTSC), чтобы PAL-игры не показывали предупреждение о регионе. (2) HDMI вместо DVI: свой лёгкий передатчик `snes_hdmi.v` (data island после HS: ACR, AVI InfoFrame VIC 1 / 17, Audio InfoFrame, сэмплы DSP ~32 кГц), DVI_ONLY из настроек firmware включает голый DVI; `tb_hdmi` декодирует TMDS и проверяет всё. LUT 12 862 → 13 289 (+427), слайсы 3 755 / 3 758 (99 %), 41 RAMB16, все ограничения выполнены. Проверено на железе (2026-10-30): звук по HDMI есть, предупреждения о регионе нет.

*Сборка 26103002 (Mini, Go)*: те же исходники, что у Mini G 26103002 (576p, Region Auto = NTSC, PAL_ID; у Mini — `snes_hdmi` со звуком, у Go — VGA и PCM5102 без изменений). Map с таблицей стоимости `-t 2` (`MAP_T_<board>` в Makefile; Mini G остаётся на `-t 1` своей сборки). Mini: LUT 12 971 → 13 500 (26102505 → 26103002), слайсы 3 748 / 3 758 (99 %); Go: 12 790 → 12 812, слайсы 3 728 (99 %); 41 RAMB16, все ограничения выполнены. На железе не проверены.

**Бэклог (следующие шаги, по порядку):**
1. *Вариант 1 (выбран автором на 2026-10-27; сделан в 26103001, работает на железе)*: PAL-игры на тайминге NTSC — Region Auto всегда NTSC (`pal_r` = 0, кроме явного выбора PAL), выход всегда 640 x 480 при 60 Гц. Игра идёт ~20 % быстрее, звук тоже (SPC на том же clk_sys) — это цена. Код 576p оставить (режим по `pal`), чтобы PAL можно было включить явно, когда появится выбор региона. Проверка: R-Type (E) на мониторе автора, Alien 3 не сломан; `tb_hdr` / `tb_video` проходят; LUT до / после.

- Перенос логики в `karabas_mini_top.v` (sigma-delta, ADC не нужен) и `karabas_go_top.v` (VGA вместо HDMI: те же 31 кГц сигналы на `VGA_R/G/B`, без DCM). Общая логика ядра — в общий модуль (`snes_system.v`, как `nes_system.v`), чтобы три верха не расходились.

## Ф5. Сохранения `.srm`

- Тот же механизм, что в Ф2 плана NES: `kg_bk_ram` в `karabas-go-modules`, `CMD_BK_MOUNT` / `CMD_IMG_FLUSH`, поле `saves` в `core.json`. Делать после NES или вместе — протокол один.
- BSRAM в SRAM, `kg_bk_ram` ходит в свой слот SRAM, игра не тормозит. Размер из `ram_size` заголовка (и правила `SNES.sv` для GSU / SA-1).
- Формат — сырой дамп, совместимый с MiSTer / snestang / эмуляторами (`.srm`).

## Ф6. Доп. чипы (в пределах ресурсов)

По остатку после Ф4:

1. DSPn (DSP-1/2/3/4, ST010/011): Super Mario Kart, Pilotwings — ПЗУ микрокода в BRAM (`dsp11b23410_p/d.hex` у snestang: 2K x 24 + 1K x 16, ~4 RAMB16).
2. OBC1, S-RTC (RTC из `kg_mcu_rtc` в `EXT_RTC`).
3. SuperFX (GSU), SA-1, CX4, SDD1, SPC7110 — по оценке не помещаются в XC6SLX25 (каждый — тысячи LUT, у MiST они отключены `EXTRA_CHIPS_*`); вернуться, только если после Ф6.1 останется > 30 % LUT.

## Ф7. Прочее (по желанию)

- PAL / регион из заголовка, отдельная частота PLL.
- Мышь SNES, мультитап, лайтган (мышью).
- SPC-плеер (`SPC_MODE` MiSTer, загрузка `.spc` в ARAM).

## Порядок и зависимости

```
Ф0 (решение: RTL, память) ─ Ф1 (каркас Mini G) ─ Ф2 (память) ─ Ф3 (SNES на Mini G) ─ Ф4 (Mini, Go)
                                                                        └─ Ф5 (.srm, общий с NES) ─ Ф6 ─ Ф7
```

- Ф1 можно делать параллельно с Ф0: каркас (клоки, MCU, HDMI, OSD) от выбора RTL не зависит.
- Ф5 зависит от `kg_bk_ram` и прошивки — синхронизировать с NES.

## Риски и открытые вопросы

- **LUT / слайсы.** Главный риск. MiST SNES на EP3C25 (24,6k LE LUT4) и snestang на GW2AR-18 (20,7k LUT4, с PicoRV32) — обнадёживающе, но 15k LUT6 / 3 758 слайсов Spartan-6 при заполнении > 90 % дают долгий PAR и плохой тайминг (опыт nanomig). Ответ — Ф0.
- **XST и VHDL MiSTer**: выражения в `port map`, возможные конструкции VHDL-2008 глубже — выяснить в Ф0. Запасной путь — Verilog snestang по модулям.
- **Тайминг 21,48 МГц**: PPU / DSP MiSTer рассчитаны на Cyclone V; на Spartan-6 -2 длинные комбинационные пути (умножители DSP, мультиплексоры PPU) — смотреть `.twr`.
- **Выход 640 x 480**: совместимость HDMI-приёмников (строки полки 797–798 тактов, DVI без InfoFrame). Запас — кадровый буфер в SDRAM.
- **SRAM на 85,94 МГц**: 2–3 клока на доступ (23–35 нс) — бюджет с учётом IOB, проверить на железе тестом памяти (`karabas-go-core-sdram-test` как образец).
- ROM > 4 МБ: в варианте A в SDRAM места хватает; ExHiROM проверить на Tales of Phantasia / Star Ocean (последний — SDD1, не пойдёт).
